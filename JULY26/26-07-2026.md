# 628. Maximum Product of Three Numbers

This repository contains my solution to the LeetCode problem **628. Maximum Product of Three Numbers** (Easy).

## Problem Statement

Given an integer array `nums`, find three numbers whose product is maximum and return the maximum product.

### Examples

**Example 1:**
```

Input: nums = [1,2,3]
Output: 6

```

**Example 2:**
```

Input: nums = [1,2,3,4]
Output: 24

```

**Example 3:**
```

Input: nums = [-1,-2,-3]
Output: -6

```

### Constraints

- `3 <= nums.length <= 10^4`
- `-1000 <= nums[i] <= 1000`

---

## Approach

The brute‑force solution would be to check every triplet, but that would be `O(n^3)` – too slow for `n = 10^4`.

Instead, we use **sorting** to reduce the problem to a constant‑time check of only two possible combinations.

### Intuition

After sorting the array in ascending order:

1. **The three largest numbers** will give a maximum product if all numbers are positive (or mostly positive).
2. However, if there are **negative numbers**, the product of two negatives is positive. So, the product of the two smallest (most negative) numbers and the largest positive number might be even greater than the product of the three largest numbers.

Thus, the maximum product is the **maximum** of these two candidates:
- `nums[n-1] * nums[n-2] * nums[n-3]` (three largest)
- `nums[0] * nums[1] * nums[n-1]` (two smallest + largest)

---

## Algorithm

1. Sort the array `nums` in non‑decreasing order.
2. Let `n = nums.length`.
3. Compute `candidate1 = nums[n-1] * nums[n-2] * nums[n-3]`.
4. Compute `candidate2 = nums[0] * nums[1] * nums[n-1]`.
5. Return `max(candidate1, candidate2)`.

---

## Code (Java)

```java
import java.util.Arrays;

class Solution {
    public int maximumProduct(int[] nums) {
        Arrays.sort(nums);
        int n = nums.length;
        
        // Option 1: three largest numbers
        int option1 = nums[n - 1] * nums[n - 2] * nums[n - 3];
        
        // Option 2: two smallest (most negative) and the largest number
        int option2 = nums[0] * nums[1] * nums[n - 1];
        
        return Math.max(option1, option2);
    }
}
```

---

Complexity Analysis

· Time Complexity: O(n log n) – due to sorting the array.
· Space Complexity: O(1) – we sort in‑place and use only a few extra variables.

Test Cases

Input Expected Output Explanation
[1, 2, 3] 6 1 * 2 * 3 = 6
[1, 2, 3, 4] 24 2 * 3 * 4 = 24
[-1, -2, -3] -6 -1 * -2 * -3 = -6
[-10, -10, 1, 2] 200 -10 * -10 * 2 = 200 (two negatives + largest)
[-100, -1, 2, 3] 300 -100 * -1 * 3 = 300
[-5, -4, -3, -2, -1] -6 -5 * -4 * -3 = -60, but -3 * -2 * -1 = -6 → max is -6 (three largest are -3,-2,-1)

---

Alternative (without sorting, O(n))

While this solution uses sorting for simplicity, an O(n) solution exists using a single pass to track the three largest and two smallest numbers. However, for n = 10^4, sorting is perfectly fine.
