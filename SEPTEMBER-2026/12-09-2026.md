# LeetCode 3414 - Maximum Score of Non-overlapping Intervals

## Problem Statement

You are given a 2D integer array `intervals`, where `intervals[i] = [lᵢ, rᵢ, weightᵢ]`.  
Interval `i` starts at `lᵢ`, ends at `rᵢ`, and has weight `weightᵢ`.

You can choose **up to 4 non-overlapping intervals**. The score is the sum of their weights.  
Return the **lexicographically smallest array of at most 4 indices** from `intervals` that achieves the maximum score.

Two intervals are **non-overlapping** if they do not share any points. Intervals sharing a left or right boundary are considered **overlapping**.

### Example 1
```
Input: intervals = [[1,3,2],[4,5,2],[1,5,5],[6,9,3],[6,7,1],[8,9,1]]
Output: [2,3]
Explanation: Choose intervals 2 and 3 with weights 5 and 3.
```

### Example 2
```
Input: intervals = [[5,8,1],[6,7,7],[4,7,3],[9,10,6],[7,8,2],[11,14,3],[3,5,5]]
Output: [1,3,5,6]
Explanation: Choose intervals 1, 3, 5, and 6 with weights 7, 6, 3, and 5.
```

### Constraints
- `1 <= intervals.length <= 5 * 10⁴`
- `intervals[i].length == 3`
- `1 <= lᵢ <= rᵢ <= 10⁹`
- `1 <= weightᵢ <= 10⁹`

---

## Approach

This is a **Weighted Interval Scheduling** variant where we can pick at most `K = 4` intervals, and we need the lexicographically smallest index list among optimal solutions.

### Step 1: Sort intervals by end time
Sort the intervals by their end time `rᵢ`. If end times are equal, sort by start time `lᵢ`.  
This ordering allows us to use dynamic programming where processing an interval only depends on previously processed intervals.

### Step 2: Precompute predecessor
For each interval `i` in the sorted order, find `p[i]` = the number of intervals that end **strictly before** `lᵢ`.  
Since intervals sharing a boundary overlap, we require `end < start`.  
This can be computed using binary search on the sorted end times.

### Step 3: Dynamic Programming
Define:
- `dp[i][j]` = maximum total weight using the first `i` sorted intervals and choosing exactly `j` intervals.
- `best[i][j]` = the lexicographically smallest sorted list of original indices achieving `dp[i][j]`.

Base case: `dp[i][0] = 0`, `best[i][0] = []`.  
For `j >= 1`, initialize to `-1` (impossible).

Transition for interval `i` (1-indexed, corresponding to sorted index `i-1`):
- **Skip** the interval: `dp[i][j] = dp[i-1][j]`, `best[i][j] = best[i-1][j]`.
- **Take** the interval: if `dp[p[i-1]][j-1] != -1`, then
  - `candidateScore = dp[p[i-1]][j-1] + weight`
  - `candidateList = merge(best[p[i-1]][j-1], originalIndex)`
  - If `candidateScore > dp[i][j]`, update.
  - If equal, keep the lexicographically smaller list.

The `merge` function inserts the original index into the already sorted list, maintaining sorted order (since we process intervals in sorted order, the original index is not necessarily larger than previous ones, so we insert in the correct position).

### Step 4: Find the answer
The maximum score is the maximum over `j = 0..4` of `dp[n][j]`.  
If multiple `j` give the same maximum score, we pick the one with the lexicographically smallest `best[n][j]`.

Return the resulting list as an `int[]`.

---

## Complexity Analysis

- **Time Complexity:**  
  Sorting: `O(n log n)`  
  Precomputing predecessors: `O(n log n)`  
  DP transitions: `O(n * K)` where `K = 4`  
  Merging lists: each list has at most 4 elements, so `O(1)` per transition.  
  Overall: `O(n log n)`.

- **Space Complexity:**  
  `dp` and `best` arrays: `O(n * K)`  
  Since `K = 4`, this is effectively `O(n)`.  
  Each `best[i][j]` stores at most 4 integers, so memory is linear.

---

## Java Solution

```java
import java.util.*;

class Solution {
    public int[] maximumWeight(List<List<Integer>> intervals) {
        int n = intervals.size();
        int[][] arr = new int[n][4];

        for (int i = 0; i < n; i++) {
            List<Integer> cur = intervals.get(i);
            arr[i][0] = cur.get(0); // start
            arr[i][1] = cur.get(1); // end
            arr[i][2] = cur.get(2); // weight
            arr[i][3] = i;          // original index
        }

        // Sort by end time, then by start time.
        Arrays.sort(arr, (a, b) -> {
            if (a[1] != b[1]) return Integer.compare(a[1], b[1]);
            return Integer.compare(a[0], b[0]);
        });

        int[] ends = new int[n];
        for (int i = 0; i < n; i++) ends[i] = arr[i][1];

        // p[i] = number of intervals that end before arr[i] starts.
        int[] p = new int[n];
        for (int i = 0; i < n; i++) {
            int start = arr[i][0];
            int lo = 0, hi = n;
            while (lo < hi) {
                int mid = lo + (hi - lo) / 2;
                if (ends[mid] < start) lo = mid + 1;
                else hi = mid;
            }
            p[i] = lo;
        }

        // dp[i][j] = max score using first i sorted intervals, choosing exactly j intervals.
        // -1 means impossible.
        long[][] dp = new long[n + 1][5];
        int[][][] best = new int[n + 1][5][];
        int[] empty = new int[0];

        for (int i = 0; i <= n; i++) {
            for (int j = 0; j <= 4; j++) {
                dp[i][j] = -1;
                best[i][j] = null;
            }
            dp[i][0] = 0;
            best[i][0] = empty;
        }

        for (int i = 1; i <= n; i++) {
            int idx = i - 1;
            int weight = arr[idx][2];
            int orig = arr[idx][3];

            for (int j = 1; j <= 4; j++) {
                // Option 1: do not take current interval.
                if (dp[i - 1][j] != -1) {
                    dp[i][j] = dp[i - 1][j];
                    best[i][j] = best[i - 1][j];
                }

                // Option 2: take current interval.
                int prev = p[idx];
                if (dp[prev][j - 1] != -1) {
                    long candScore = dp[prev][j - 1] + weight;
                    int[] candList = merge(best[prev][j - 1], orig);

                    if (dp[i][j] == -1 || candScore > dp[i][j]) {
                        dp[i][j] = candScore;
                        best[i][j] = candList;
                    } else if (candScore == dp[i][j]) {
                        if (compare(candList, best[i][j]) < 0) {
                            best[i][j] = candList;
                        }
                    }
                }
            }
        }

        long maxScore = -1;
        int[] ans = null;

        for (int j = 0; j <= 4; j++) {
            if (dp[n][j] == -1) continue;
            if (dp[n][j] > maxScore) {
                maxScore = dp[n][j];
                ans = best[n][j];
            } else if (dp[n][j] == maxScore) {
                if (ans == null || compare(best[n][j], ans) < 0) {
                    ans = best[n][j];
                }
            }
        }

        return ans == null ? new int[0] : ans;
    }

    private int[] merge(int[] prev, int idx) {
        int len = prev.length;
        int[] res = new int[len + 1];
        int i = 0, j = 0;

        while (i < len && prev[i] < idx) {
            res[j++] = prev[i++];
        }
        res[j++] = idx;
        while (i < len) {
            res[j++] = prev[i++];
        }

        return res;
    }

    private int compare(int[] a, int[] b) {
        if (a == null) return b == null ? 0 : 1;
        if (b == null) return -1;

        int len = Math.min(a.length, b.length);
        for (int i = 0; i < len; i++) {
            if (a[i] != b[i]) return a[i] - b[i];
        }
        return a.length - b.length;
    }
}
```

## Notes

- The DP uses `long` for scores because weights can be up to `10⁹` and we may sum up to 4 of them, which fits in `long` (and even in `int` up to ~4×10⁹, but `long` is safer).
- The `best` arrays store the original indices (0-based) in sorted order.
- Lexicographic comparison of arrays: shorter array is considered smaller if it is a prefix of the longer one. This matches the problem's requirement (e.g., `[2,3]` is lexicographically smaller than `[2,3,4]`).
- The solution handles up to 4 intervals, but can be easily generalized to any `K` by changing the constant `4`.
