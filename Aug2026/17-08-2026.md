# 1563. Stone Game V

This repository contains a Java solution for LeetCode problem [1563. Stone Game V](https://leetcode.com/problems/stone-game-v/).

## Problem Statement

There are several stones arranged in a row, and each stone has an associated value which is an integer given in the array `stoneValue`.

In each round of the game, Alice divides the row into two non-empty rows (i.e. left row and right row), then Bob calculates the value of each row which is the sum of the values of all the stones in this row. Bob throws away the row which has the maximum value, and Alice's score increases by the value of the remaining row. If the value of the two rows are equal, Bob lets Alice decide which row will be thrown away. The next round starts with the remaining row.

The game ends when there is only one stone remaining. Alice's score is initially zero.

Return the **maximum score** that Alice can obtain.

## Examples

### Example 1
```
Input: stoneValue = [6,2,3,4,5,5]
Output: 18
Explanation:
- Round 1: Divide [6,2,3] and [4,5,5]. Left sum=11, Right sum=14. Bob throws away right. Score=11. Remaining: [6,2,3].
- Round 2: Divide [6] and [2,3]. Left sum=6, Right sum=5. Bob throws away left. Score=11+5=16. Remaining: [2,3].
- Round 3: Divide [2] and [3]. Left sum=2, Right sum=3. Bob throws away right. Score=16+2=18. Remaining: [2] (one stone left, game ends).
```


## Constraints

- `1 <= stoneValue.length <= 500`
- `1 <= stoneValue[i] <= 10^6`

---

## Solution Approach

### Dynamic Programming (Bottom-Up)

We define `dp[l][r]` as the maximum score Alice can obtain from the subarray `stoneValue[l...r]` (inclusive).

#### Key Observations

- If `l == r` (only one stone), the game ends immediately, so `dp[l][r] = 0`.
- For any split point `k` where `l <= k < r`, we divide the interval into:
  - Left part: `[l, k]` → sum = `leftSum`
  - Right part: `[k+1, r]` → sum = `rightSum`

- Bob removes the part with the larger sum. The remaining part continues to the next round.
- The score for this split is:
  - If `leftSum < rightSum`: Bob removes the right. Alice gains `leftSum` + optimal score from the left part → `leftSum + dp[l][k]`
  - If `leftSum > rightSum`: Bob removes the left. Alice gains `rightSum` + optimal score from the right part → `rightSum + dp[k+1][r]`
  - If `leftSum == rightSum`: Alice can choose which part remains (to maximize her score), so she gains `leftSum + max(dp[l][k], dp[k+1][r])`

- We take the maximum over all possible split points `k`.

#### Optimization

- Prefix sums are used to calculate `leftSum` and `rightSum` in **O(1)** time.
- We iterate over interval lengths from `2` to `n`, filling the `dp` table in a bottom-up manner.

## Code

```java
class Solution {
    public int stoneGameV(int[] stoneValue) {
        int n = stoneValue.length;
        
        // Prefix sums for O(1) range sum queries
        int[] prefix = new int[n + 1];
        for (int i = 0; i < n; i++) {
            prefix[i + 1] = prefix[i] + stoneValue[i];
        }
        
        // dp[l][r] = maximum score Alice can get from interval [l, r]
        int[][] dp = new int[n][n];
        
        // Iterate by interval length
        for (int len = 2; len <= n; len++) {
            for (int l = 0; l + len - 1 < n; l++) {
                int r = l + len - 1;
                int best = 0;
                
                // Try every possible split point
                for (int k = l; k < r; k++) {
                    int leftSum = prefix[k + 1] - prefix[l];
                    int rightSum = prefix[r + 1] - prefix[k + 1];
                    
                    int score;
                    if (leftSum < rightSum) {
                        score = leftSum + dp[l][k];
                    } else if (leftSum > rightSum) {
                        score = rightSum + dp[k + 1][r];
                    } else {
                        // Bob lets Alice choose which row remains
                        score = leftSum + Math.max(dp[l][k], dp[k + 1][r]);
                    }
                    
                    best = Math.max(best, score);
                }
                
                dp[l][r] = best;
            }
        }
        
        return dp[0][n - 1];
    }
}
```

---

## Complexity Analysis

- **Time Complexity:** `O(n^3)`
  - For each interval (there are `O(n^2)` intervals), we iterate over all split points `k` (up to `O(n)`). The total complexity is `O(n^3)`.
  - Given `n <= 500`, this is acceptable (125 million operations, manageable in Java with optimization).

- **Space Complexity:** `O(n^2)`
  - The `dp` table of size `n x n`.
