# 877. Stone Game

## Problem Statement

Alice and Bob play a game with piles of stones. There are an **even** number of piles arranged in a row, and each pile has a positive integer number of stones `piles[i]`.  

The objective is to end with the most stones. The **total** number of stones across all piles is **odd**, so there are no ties.  

- Alice starts first.
- On each turn, a player takes the entire pile from either the **beginning** or the **end** of the row.
- The game continues until no piles remain. The player with more stones wins.

Given that both play **optimally**, return `true` if Alice wins, or `false` if Bob wins.

### Examples

**Example 1:**
```
Input: piles = [5,3,4,5]
Output: true
Explanation:
Alice can take the first 5 or the last 5.
If she takes first 5, row becomes [3,4,5].
- If Bob takes 3, row [4,5], Alice takes 5 → total 10 vs Bob 3 → win.
- If Bob takes 5, row [3,4], Alice takes 4 → total 9 vs Bob 5 → win.
So Alice can force a win.
```

**Example 2:**
```
Input: piles = [3,7,2,3]
Output: true
```

---

## Key Insight: Alice Always Wins

Because the number of piles is **even** and the total sum is **odd**, Alice has a guaranteed winning strategy:

- Consider all piles at **even indices** (0, 2, 4, …) and all at **odd indices** (1, 3, 5, …).
- The sum of all stones is odd, so the two sums cannot be equal. One of them is strictly larger.
- Alice can decide at the start which parity (even or odd) she wants to collect.
- Since she moves first, she can always pick from an end such that she eventually takes all piles of the chosen parity.
- She chooses the parity with the **larger sum**, guaranteeing she ends with more stones than Bob.

Thus, **Alice always wins**. The function simply returns `true`.

### Why This Works

- There are only two ways to partition the row into alternating positions.  
- When Alice takes a pile from one end, the remaining ends always belong to the opposite parity group.  
- By sticking to the same parity, Alice can force Bob to take only the other parity.  
- Since the total sum is odd, the two parity sums differ, so Alice’s chosen sum > Bob’s sum.

## Implementation

### Simplest Solution – Return `true`
```java
class Solution {
    public boolean stoneGame(int[] piles) {
        // Alice always wins due to parity argument
        return true;
    }
}
```

### Dynamic Programming Solution (for generalisation)
Though not needed for this specific problem, we can solve it using the same DP approach as in **Predict the Winner** (LeetCode 486).  
`dp[i][j]` = maximum score difference the current player can achieve from subarray `piles[i..j]`.

```java
class Solution {
    public boolean stoneGame(int[] piles) {
        int n = piles.length;
        int[][] dp = new int[n][n];
        
        for (int i = 0; i < n; i++) {
            dp[i][i] = piles[i];
        }
        
        for (int len = 2; len <= n; len++) {
            for (int i = 0; i + len - 1 < n; i++) {
                int j = i + len - 1;
                dp[i][j] = Math.max(
                    piles[i] - dp[i+1][j],
                    piles[j] - dp[i][j-1]
                );
            }
        }
        
        return dp[0][n-1] > 0;  // Alice wins if difference > 0
    }
}
```

## Complexity Analysis

- **Simplest solution:**  
  - Time: O(1)  
  - Space: O(1)

- **DP solution:**  
  - Time: O(n²)  
  - Space: O(n²) (can be optimised to O(n))

## Notes

- This problem is a special case of **Predict the Winner** where the array length is even and total sum is odd.

- Even though the DP solution is valid, the `return true` solution is sufficient and expected for this problem.
