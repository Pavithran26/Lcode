# 1406. Stone Game III

[LeetCode Problem Link](https://leetcode.com/problems/stone-game-iii/)

## Problem Description

Alice and Bob continue their game with piles of stones. There are several stones arranged in a row, and each stone has an associated integer value given in the array `stoneValue`.

Alice and Bob take turns, with Alice starting first. On each player's turn, that player can take **1, 2, or 3** stones from the first remaining stones in the row.

The score of each player is the sum of the values of the stones taken. Both players start with a score of 0.

The objective is to end with the highest score. The winner is the player with the higher score; a tie is possible. The game continues until all stones are taken.

Assume both players play **optimally**. Return `"Alice"` if Alice wins, `"Bob"` if Bob wins, or `"Tie"` if they end with the same score.

### Examples

**Example 1:**

```
Input: stoneValue = [1,2,3,7]
Output: "Bob"
Explanation: Alice will always lose. Her best move is to take three piles and get score 6. Then Bob gets 7 and wins.
```

**Example 2:**

```
Input: stoneValue = [1,2,3,-9]
Output: "Alice"
Explanation: Alice must take all three piles on her first move to win and leave Bob with a negative score.
If she takes one pile, she gets 1, Bob gets 5, then Alice gets -9 and loses.
If she takes two piles, she gets 3, Bob gets 3, then Alice gets -9 and loses.
Both play optimally, so Alice chooses the winning scenario.
```

**Example 3:**

```
Input: stoneValue = [1,2,3,6]
Output: "Tie"
Explanation: Alice cannot win. She can draw by taking the first three piles; otherwise she loses.
```

## Solution Approach

This is a classic **dynamic programming** game theory problem.

### State Definition

Let `dp[i]` be the **best relative score** (current player's total score minus opponent's total score) that the current player can achieve from the subarray `stoneValue[i..n-1]`.

### Transition

The current player can take 1, 2, or 3 stones. After taking them, the opponent becomes the current player for the remaining piles.

- Take 1 stone: gain `stoneValue[i]`, then the opponent will have `dp[i+1]` relative advantage over us. So our relative score becomes `stoneValue[i] - dp[i+1]`.
- Take 2 stones: gain `stoneValue[i] + stoneValue[i+1]`, then opponent's relative score from `i+2` is `dp[i+2]`, so we get `stoneValue[i] + stoneValue[i+1] - dp[i+2]` (if `i+1 < n`).
- Take 3 stones: gain `stoneValue[i] + stoneValue[i+1] + stoneValue[i+2]`, then opponent's relative score from `i+3` is `dp[i+3]`, so we get `stoneValue[i] + stoneValue[i+1] + stoneValue[i+2] - dp[i+3]` (if `i+2 < n`).

We take the maximum of these options:

```
dp[i] = max(
    stoneValue[i] - dp[i+1],
    stoneValue[i] + stoneValue[i+1] - dp[i+2]   (if i+1 < n),
    stoneValue[i] + stoneValue[i+1] + stoneValue[i+2] - dp[i+3]   (if i+2 < n)
)
```

Base case: `dp[n] = 0` (no stones left).

### Final Decision

Compute `dp[0]` – the relative score for Alice (who starts).

- If `dp[0] > 0` → Alice wins.
- If `dp[0] < 0` → Bob wins.
- If `dp[0] == 0` → Tie.

## Code Implementation (Java)

```java
class Solution {
    public String stoneGameIII(int[] stoneValue) {
        int n = stoneValue.length;
        int[] dp = new int[n + 1];
        dp[n] = 0; // no stones left

        for (int i = n - 1; i >= 0; i--) {
            // Take 1 stone
            int best = stoneValue[i] - dp[i + 1];

            // Take 2 stones
            if (i + 1 < n) {
                best = Math.max(best, stoneValue[i] + stoneValue[i + 1] - dp[i + 2]);
            }

            // Take 3 stones
            if (i + 2 < n) {
                best = Math.max(best,
                    stoneValue[i] + stoneValue[i + 1] + stoneValue[i + 2] - dp[i + 3]);
            }

            dp[i] = best;
        }

        if (dp[0] > 0) return "Alice";
        if (dp[0] < 0) return "Bob";
        return "Tie";
    }
}
```

## Complexity Analysis

- **Time Complexity:** O(n) – one pass over the array.
- **Space Complexity:** O(n) for the DP array. Can be reduced to O(1) by keeping only the last three DP values, but O(n) is clear and acceptable for `n ≤ 5×10⁴`.

## Summary

This problem is solved by defining a DP that tracks the **maximum relative score** for the current player. The transition considers all three possible moves, and the final sign of `dp[0]` determines the winner. The solution is efficient and handles negative values gracefully.
