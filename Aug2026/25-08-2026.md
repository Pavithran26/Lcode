# 1872. Stone Game VIII

[![LeetCode](https://img.shields.io/badge/LeetCode-Hard-red)](https://leetcode.com/problems/stone-game-viii/)
[![Java](https://img.shields.io/badge/Java-17%2B-blue)]()

## Problem Statement

Alice and Bob take turns playing a game, with **Alice starting first**.

There are `n` stones arranged in a row. On each player's turn, while the number of stones is more than one, they will do the following:

1. Choose an integer `x > 1`, and remove the leftmost `x` stones from the row.
2. Add the sum of the removed stones' values to the player's score.
3. Place a new stone, whose value is equal to that sum, on the left side of the row.

The game stops when **only one** stone is left in the row.

The **score difference** between Alice and Bob is `(Alice's score - Bob's score)`. Alice's goal is to **maximize** the score difference, and Bob's goal is to **minimize** the score difference.

Given an integer array `stones` of length `n` where `stones[i]` represents the value of the stone from the left, return the score difference between Alice and Bob if they both play optimally.

---

## Examples

### Example 1:
```

Input: stones = [-1, 2, -3, 4, -5]
Output: 5

```
**Explanation:**
- Alice removes the first 4 stones, adds `(-1) + 2 + (-3) + 4 = 2` to her score, and places a stone of value `2` on the left. `stones = [2, -5]`.
- Bob removes the first 2 stones, adds `2 + (-5) = -3` to his score, and places a stone of value `-3` on the left. `stones = [-3]`.
- The difference is `2 - (-3) = 5`.

### Example 2:
```

Input: stones = [7, -6, 5, 10, 5, -2, -6]
Output: 13

```
**Explanation:**
- Alice removes all stones, adds `7 + (-6) + 5 + 10 + 5 + (-2) + (-6) = 13` to her score, and places a stone of value `13` on the left. `stones = [13]`.
- The difference is `13 - 0 = 13`.

### Example 3:
```

Input: stones = [-10, -12]
Output: -22

```
**Explanation:**
- Alice can only make one move, which is to remove both stones. She adds `(-10) + (-12) = -22` to her score and places a stone of value `-22` on the left.
- The difference is `(-22) - 0 = -22`.

---

## Constraints

- `n == stones.length`
- `2 <= n <= 10^5`
- `-10^4 <= stones[i] <= 10^4`

---

## Approach

### Key Insight

Notice that after each move, the row always contains a single stone on the left whose value is the prefix sum of the removed segment, followed by the remaining untouched stones.

Let `prefix[i]` be the sum of the first `i` stones (i.e., `stones[0]` to `stones[i-1]`).

If a player chooses to remove the leftmost `x` stones when the current left stone represents `prefix[i]` (where `i` is the number of original stones consumed so far), they gain `prefix[i + x] - prefix[i]` points, and the new left stone becomes `prefix[i + x]`.

Instead of tracking the exact stone values, we can view the game as:
- The state is defined by the index `i` (how many original stones have been consumed into the left stone).
- The player to move chooses a new index `j > i` (with `j - i >= 1`, but `x > 1` means `j - i > 1`, so `j >= i + 2`).
- They earn `prefix[j] - prefix[i]` points, and the state becomes `j`.
- The game ends when `j = n`.

### Dynamic Programming

Let `dp[i]` be the **optimal score difference** (current player's total score minus other player's total score) from the state where the left stone has value `prefix[i]` and it is the current player's turn.

The current player can choose any `j` in `[i+2, n]`, earning `prefix[j] - prefix[i]` immediately. Then the opponent plays from state `j`, yielding `-dp[j]` relative to the current player.

So the recurrence is:

```

dp[i] = max_{j in [i+2 .. n]} ( prefix[j] - prefix[i] - dp[j] )

```

This is equivalent to:

```

dp[i] = -prefix[i] + max_{j in [i+2 .. n]} ( prefix[j] - dp[j] )

```

We can compute this from right to left:

- `dp[n] = 0` (no move possible).
- For `i` from `n-1` down to `2`:
  - `dp[i] = max_{j > i} ( prefix[j] - dp[j] ) - prefix[i]`.
  - We maintain a running maximum `best = max_{j > i} ( prefix[j] - dp[j] )`.

Finally, Alice starts with `i = 0`? Wait, the first move must remove `x > 1`, so she chooses `j` in `[2, n]`. Her score difference is:

```

answer = max_{j in [2..n]} ( prefix[j] - dp[j] )

```

Which is exactly the `best` value after processing down to `i=2`.

### Optimized Implementation

We only need to maintain the suffix maximum `best`, so no explicit `dp` array is needed. The loop runs in `O(n)` time.

## Code

```java
class Solution {
    public int stoneGameVIII(int[] stones) {
        int n = stones.length;

        // prefix[i] = sum of first i stones
        long[] prefix = new long[n + 1];
        for (int i = 0; i < n; i++) {
            prefix[i + 1] = prefix[i] + stones[i];
        }

        // best = max_{j > i} (prefix[j] - dp[j])
        // Initially for i = n-1, the only j > i is n.
        // dp[n] = 0, so best = prefix[n] - 0 = prefix[n].
        long best = prefix[n];

        // Compute optimal for i from n-1 down to 2.
        // We stop at i=2 because Alice's first move must have j >= 2.
        for (int i = n - 1; i >= 2; i--) {
            // dp[i] = best - prefix[i]
            long dpI = best - prefix[i];

            // Update best for the next iteration (i-1):
            // best = max(best, prefix[i] - dp[i])
            best = Math.max(best, prefix[i] - dpI);
        }

        return (int) best;
    }
}
```

Complexity Analysis

Complexity Value
Time O(n) – single pass to compute prefix sums and single backward pass for DP.
Space O(n) – for the prefix sum array. Could be reduced to O(1) with a single total sum variable, but this version prioritizes clarity.
