# 2996. Smallest Missing Integer Greater Than Sequential Prefix Sum

**LeetCode Problem:** [2996. Smallest Missing Integer Greater Than Sequential Prefix Sum](https://leetcode.com/problems/smallest-missing-integer-greater-than-sequential-prefix-sum/)  
**Difficulty:** Easy  
**Topics:** Array, Hash Table

---

## Problem Statement

You are given a **0‑indexed** array of integers `nums`.

A **prefix** `nums[0..i]` is **sequential** if for all `1 <= j <= i`, `nums[j] = nums[j - 1] + 1`.  
In particular, the prefix consisting only of `nums[0]` is always sequential.

Your task is to return the **smallest** integer `x` missing from `nums` such that `x` is **greater than or equal** to the sum of the **longest sequential prefix**.

---

### Examples

#### Example 1
```
Input: nums = [1,2,3,2,5]
Output: 6
Explanation:
The longest sequential prefix is [1,2,3] with sum = 6.
6 is not in the array, therefore 6 is the smallest missing integer ≥ 6.
```

#### Example 2
```
Input: nums = [3,4,5,1,12,14,13]
Output: 15
Explanation:
The longest sequential prefix is [3,4,5] with sum = 12.
12, 13, and 14 are present in the array, but 15 is not.
Therefore 15 is the answer.
```

---

## Approach

1. **Find the Longest Sequential Prefix**  
   - Start from index `0`.
   - While the next element equals `current + 1`, extend the prefix.
   - The prefix stops at the first break in the consecutive sequence.

2. **Compute its Sum**  
   - Sum all elements from `0` to the end index of that prefix.

3. **Use a Set for O(1) Lookups**  
   - Insert all numbers from `nums` into a `HashSet`.

4. **Search for the Missing Integer**  
   - Let `candidate = sum`.
   - While `candidate` is present in the set, increment `candidate`.
   - The first value not in the set is the answer.

---

### Algorithm Steps

```
1. Let n = nums.length
2. Let i = 0
3. While i+1 < n and nums[i+1] == nums[i] + 1:
       i++
4. Compute sum = nums[0] + ... + nums[i]
5. Build a HashSet from nums
6. Initialize candidate = sum
7. While candidate is in the set:
       candidate++
8. Return candidate
```

---

### Complexity Analysis

- **Time Complexity:** `O(n)`
  - Finding the prefix takes `O(n)` worst-case.
  - Building the set takes `O(n)`.
  - The while loop for missing integer increments at most up to the maximum possible missing value; but since `nums[i] ≤ 50` and `n ≤ 50`, the loop is bounded by a constant factor; formally it is `O(n + max(nums))` which is effectively `O(n)`.
- **Space Complexity:** `O(n)` for the hash set.

---

## Java Solution

```java
class Solution {
    public int missingInteger(int[] nums) {
        int n = nums.length;
        
        // Find the longest sequential prefix
        int i = 0;
        while (i + 1 < n && nums[i + 1] == nums[i] + 1) {
            i++;
        }
        
        // Compute sum of that prefix
        int sum = 0;
        for (int j = 0; j <= i; j++) {
            sum += nums[j];
        }
        
        // Store all numbers for O(1) lookup
        Set<Integer> set = new HashSet<>();
        for (int num : nums) {
            set.add(num);
        }
        
        // Find smallest missing integer >= sum
        int candidate = sum;
        while (set.contains(candidate)) {
            candidate++;
        }
        return candidate;
    }
}
```

---

## Edge Cases

- **Single element:** e.g., `nums = [5]` → longest prefix is `[5]`, sum = `5`. Set contains `5`. `candidate` becomes `6` (since 5 is present), return `6`.
- **All elements form a long consecutive prefix:** e.g., `nums = [1,2,3,4]` → prefix sum = `10`. If array doesn't contain `10`, return `10`. If it does, continue.
- **Duplicate numbers:** handled correctly because we only care about membership, not counts.

---

## Additional Notes

- The problem constraints are small (`n ≤ 50`, `nums[i] ≤ 50`), so even a brute‑force check from `sum` upward would be fine, but the set approach is clean and efficient.
- The prefix must start at index `0`; we only consider prefixes that begin at the very first element.
