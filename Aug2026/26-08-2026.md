# 2904. Shortest and Lexicographically Smallest Beautiful String

## Problem Statement

You are given a binary string `s` and a positive integer `k`.

A substring of `s` is **beautiful** if the number of `1`'s in it is exactly `k`.

Let `len` be the length of the **shortest beautiful** substring.

Return the **lexicographically smallest beautiful** substring of string `s` with length equal to `len`. If `s` doesn't contain a beautiful substring, return an empty string.

**Lexicographic order**: A string `a` is lexicographically **larger than** string `b` (of the same length) if at the first position where they differ, `a` has a character strictly larger than the corresponding character in `b`.

---

### Examples

#### Example 1
```

Input: s = "100011001", k = 3
Output: "11001"

```
**Explanation:**  
There are 7 beautiful substrings (all have exactly three `1`s). The shortest beautiful substring length is 5. Among all substrings of length 5 with three `1`s, the lexicographically smallest is `"11001"`.

#### Example 2
```

Input: s = "1011", k = 2
Output: "11"

```
**Explanation:**  
Beautiful substrings are `"1011"` (the whole string has two `1`s) and other substrings that contain exactly two `1`s. The shortest length is 2, and the smallest lexicographically is `"11"`.

#### Example 3
```

Input: s = "000", k = 1
Output: ""

```
**Explanation:**  
There is no substring with exactly one `1`, so return an empty string.

---

## Constraints
- `1 <= s.length <= 100`
- `1 <= k <= s.length`

---

## Approach

We need to find all beautiful substrings (substrings containing exactly `k` ones), track the minimum length, and then select the lexicographically smallest among those with that minimum length.

Since the string length is at most 100, a brute‑force O(n²) solution is acceptable.

### Algorithm
1. Initialize `minLen` to a large value and `answer` to an empty string.
2. Iterate over all possible starting indices `i` from `0` to `n-1`:
   - Maintain a count of ones (`ones`) starting from 0.
   - For each ending index `j` from `i` to `n-1`:
     - If `s[j] == '1'`, increment `ones`.
     - If `ones > k`, break the inner loop (because further extension will only add more ones).
     - If `ones == k`:
       - Compute substring `sub = s.substring(i, j+1)` and its length `len`.
       - If `len < minLen`, update `minLen` and set `answer = sub`.
       - Else if `len == minLen` and `sub` is lexicographically smaller than `answer`, update `answer = sub`.
       - Since we found a beautiful substring starting at `i` with exactly `k` ones, any longer substring starting at the same `i` would have more than `k` ones (if we extend further) – but actually we could extend while keeping exactly `k` ones if there are zeros in between? Wait, if we have exactly `k` ones up to `j`, then extending to `j+1` might add a zero (so ones still `k`) or a one (ones becomes `k+1`). To avoid missing shorter substrings with same number of ones, we should not break immediately after finding a beautiful substring; we might continue to find other substrings of the same length or longer. However, since we are looking for shortest length, if we find a beautiful substring at length `len`, any longer substring from the same `i` will have length > `len`, so we can safely break because we already have the shortest for that starting index. But we must consider that there might be another substring starting at `i` with the same length but different content? Actually, if we fix `i` and move `j` forward, the length increases. The first time we hit `k` ones gives a certain length, and further extensions either keep the ones count (if zeros) or increase it (if ones). If further extensions keep ones count (by adding zeros), then they have longer length, so they cannot be the shortest overall if we already found a shorter one. So breaking is safe for finding the minimum length per start. But we need to consider lexicographically smallest among equal shortest lengths, which we handle when lengths match. So breaking after finding a beautiful substring is safe because any further extension will have greater length, which cannot beat the current minimum length (but could equal if current minLen is already larger? Actually if we break early, we might miss a longer substring of length equal to the current minLen if that minLen was set by another start? But we are only considering substrings starting at `i`; if we break, we don't consider longer substrings starting at `i`. However, we already have a beautiful substring of length `len` from this `i`. If the global `minLen` is larger than `len`, we update. Later, if we find another starting index `i'` that also yields the same `len`, we compare lexicographically. But what if there is a longer substring starting at the same `i` that also has length equal to the global minimum length? That can only happen if the global minimum length equals that longer length, but since we already have a shorter one from that `i`, the global minimum will be at most that shorter length, so a longer one cannot be the shortest. Hence breaking is correct.
   - Continue outer loop.
3. Return `answer` (which will be empty if no beautiful substring found).

### Complexity
- **Time:** O(n²) – we iterate all substrings.
- **Space:** O(n) for substring extraction (though we can use `substring` which creates a new string; overall O(n²) for intermediate strings, but manageable given n ≤ 100).

---

## Java Solution

```java
class Solution {
    public String shortestBeautifulSubstring(String s, int k) {
        int n = s.length();
        int minLen = Integer.MAX_VALUE;
        String answer = "";

        for (int i = 0; i < n; i++) {
            int ones = 0;

            for (int j = i; j < n; j++) {
                if (s.charAt(j) == '1') {
                    ones++;
                }

                if (ones > k) break;

                if (ones == k) {
                    int len = j - i + 1;
                    String sub = s.substring(i, j + 1);

                    if (len < minLen) {
                        minLen = len;
                        answer = sub;
                    } else if (len == minLen && sub.compareTo(answer) < 0) {
                        answer = sub;
                    }

                    // Break because further extension will only increase length
                    // and cannot be shorter than the current 'len'.
                    break;
                }
            }
        }

        return answer;
    }
}
```

---

Notes

· The problem guarantees k >= 1 and s contains only '0' and '1'.
· If there are multiple shortest beautiful substrings, the lexicographically smallest is chosen (i.e., the one with the smaller character at the first differing position).
· The solution is straightforward and passes all test cases under the given constraints.
