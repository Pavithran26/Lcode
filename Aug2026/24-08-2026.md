## Problem Statement

Given an integer array `nums` and an integer `k`, return the **smallest positive multiple of `k`** that is **missing** from `nums`.

A **multiple of `k`** is any positive integer divisible by `k`.

---

### Examples

#### Example 1:
```
Input: nums = [8,2,3,4,6], k = 2
Output: 10
Explanation:
The multiples of k = 2 are 2, 4, 6, 8, 10, 12, ...
The smallest multiple missing from nums is 10.
```

#### Example 2:
```
Input: nums = [1,4,7,10,15], k = 5
Output: 5
Explanation:
The multiples of k = 5 are 5, 10, 15, 20, ...
The smallest multiple missing from nums is 5.
```

---

### Constraints
- `1 <= nums.length <= 100`
- `1 <= nums[i] <= 100`
- `1 <= k <= 100`

---

## Solution Approach

### Intuition
We need to find the first positive multiple of `k` that does **not** appear in the given array.

The simplest approach:
1. Store all elements of `nums` in a hash set for O(1) lookups.
2. Start checking multiples of `k` from `k` upwards.
3. The first multiple not present in the set is the answer.

Since `k` and array values are limited to 100, but the missing multiple could be larger than 100 (e.g., Example 1 gives 10 even though array values are <= 8). However, the answer will not be unbounded because we only need to check until we find a missing multiple; in the worst case, if all first few multiples are present, we might have to go beyond the maximum array value. But since the array size is at most 100, the answer is at most `k * (nums.length + 1)` (because there are at most 100 distinct multiples that could be present, so the (101)th multiple must be missing). So it's safe.

### Algorithm
1. Create a `HashSet<Integer>` and add all elements of `nums`.
2. Initialize `multiple = k`.
3. While `set.contains(multiple)`:
   - `multiple += k`
4. Return `multiple`.

### Complexity Analysis
- **Time Complexity:** O(n + m) where `n = nums.length` and `m` is the number of multiples we check until we find a missing one. In the worst case, `m` is at most `n + 1` because only `n` distinct multiples can be present. So overall O(n).
- **Space Complexity:** O(n) for the hash set.

## Code

### Java
```java
import java.util.HashSet;
import java.util.Set;

class Solution {
    public int missingMultiple(int[] nums, int k) {
        Set<Integer> present = new HashSet<>();
        for (int num : nums) {
            present.add(num);
        }

        int multiple = k;
        while (present.contains(multiple)) {
            multiple += k;
        }

        return multiple;
    }
}
```

### Alternative (without HashSet – using boolean array)
Since constraints are small (values up to 100, but the answer may exceed 100), we can still use a boolean array of size maybe 10000, but hash set is cleaner.

## Notes
- The problem guarantees that an answer always exists (since there are infinitely many multiples of `k`, and only finitely many are in the array).
- This solution uses a hash set for clarity; given the small constraints, one could also sort and iterate, but set is optimal.
