1927. Sum Game

📜 Problem Statement

Alice and Bob play a game on a string num of even length, containing digits ('0'–'9') and '?' characters.

· Alice moves first.
· On each turn, a player picks an index i where num[i] == '?' and replaces it with any digit from '0' to '9'.
· The game ends when there are no more '?' characters.
· Bob wins if the sum of digits in the first half equals the sum of digits in the second half.
· Alice wins if the sums are not equal.

Assuming both play optimally, return true if Alice can force a win, otherwise false.

Examples

Input Output Explanation
"25??" true Alice can put '9' in the right half, making it impossible for Bob to balance the sums.
"?3295???" false Bob can always force a tie regardless of Alice's moves.

Constraints

· 2 <= num.length <= 10^5
· num.length is even.
· num consists only of digits and '?'.

---

🧠 Intuition

Let’s split the string into two halves:

· Left half: L
· Right half: R

Define:

· sumDiff = sum(L_digits) - sum(R_digits)
· cntDiff = count('?' in L) - count('?' in R)

A key observation is that Bob can force a win (i.e., make the sums equal) if and only if:

```
2 * sumDiff + 9 * cntDiff == 0
```

If this condition holds, Bob wins (false). Otherwise, Alice wins (true).

---

🔍 Why does this work?

Let’s examine the effect of replacing a '?' with a digit:

· If a player puts digit x in the left half, sumDiff increases by x.
· If a player puts digit x in the right half, sumDiff decreases by x.

Alice wants the final sumDiff to be non‑zero. Bob wants it to be zero.

The total number of '?' in each half determines how much sumDiff can be shifted.
The maximum total shift possible (in absolute value) from all '?' is:

· Each '?' in the left can contribute up to +9.
· Each '?' in the right can contribute down to -9 (i.e., up to -9).

After simplification, the final reachable values of sumDiff form an arithmetic progression.
The only way Bob can guarantee sumDiff = 0 despite Alice’s optimal interference is when the initial sumDiff is exactly -(9 * cntDiff) / 2.

That condition is exactly:

```
2 * sumDiff + 9 * cntDiff == 0
```

If this is 0, Bob has a strategy to mirror Alice’s moves and always land on zero.
Otherwise, Alice can exploit the imbalance and force a non‑zero result.

---

⚙️ Algorithm

1. Compute sumDiff and cntDiff by iterating through the string:
   · For positions in the first half:
     · If '?', increment cntDiff.
     · Else, add digit to sumDiff.
   · For positions in the second half:
     · If '?', decrement cntDiff.
     · Else, subtract digit from sumDiff.
2. Check the condition:
   ```
   if (2 * sumDiff + 9 * cntDiff == 0) return false;
   else return true;
   ```

---

💻 Code (Java)

```java
class Solution {
    public boolean sumGame(String num) {
        int n = num.length();
        int half = n / 2;

        int sumDiff = 0; // sum(left digits) - sum(right digits)
        int cntDiff = 0; // count('?' in left) - count('?' in right)

        for (int i = 0; i < n; i++) {
            char c = num.charAt(i);

            if (i < half) {
                if (c == '?') cntDiff++;
                else sumDiff += c - '0';
            } else {
                if (c == '?') cntDiff--;
                else sumDiff -= c - '0';
            }
        }

        // Bob wins iff the following condition is 0
        return 2 * sumDiff + 9 * cntDiff != 0;
    }
}
```

---

📊 Complexity

· Time Complexity: O(n) — one pass through the string.
· Space Complexity: O(1) — only a few integer variables.

---

✅ Correctness Proof (Sketch)

· Invariant: After each pair of moves (Alice then Bob), the value of 2 * sumDiff + 9 * cntDiff remains unchanged.
· If the initial value is 0, Bob can always respond to Alice’s move by choosing a digit that restores the invariant, ultimately ending with sumDiff = 0.
· If the initial value is not 0, Alice can make her first move to break any chance of balance, and the invariant prevents Bob from ever reaching 0.

This proves the optimality of the condition.

🧪 Test Examples

```java
new Solution().sumGame("25??");     // true
new Solution().sumGame("?3295???"); // false
new Solution().sumGame("??");       // true (Alice can pick 9, Bob picks 0 → sums not equal)
new Solution().sumGame("9?");       // false? Let's check: half=1, left=9, right=? → sumDiff=9, cntDiff=-1 → 18-9=9 !=0 → true. Correct.
```

📌 Key Takeaway

This problem is a classic game theory + greedy problem, reduced to a simple arithmetic condition. No simulation or minimax is needed due to the symmetry of the moves.
